Sistema Automatizado para el Control de Asistencia

1. Arquitectura del Sistema

El presente archivo ha sido programado bajo estrictos estándares institucionales, utilizando procesos automatizados en segundo plano (VBA). Esto significa que el usuario no requiere interactuar con fórmulas complejas. La integridad de los datos está garantizada, reduciendo el margen de error humano a cero mediante validaciones lógicas en tiempo real.

Garantía de Operabilidad: El diseño "Zero-Formulas" asegura que ninguna celda de cálculo puede ser eliminada por accidente. El sistema opera de manera autónoma al detectar el ingreso de datos por parte del usuario.

2. Operación del Anexo 03 (Registro Detallado)

Este formato constituye el "Motor de Datos" principal. Toda la información ingresada aquí alimentará automáticamente los reportes consolidados (Anexo 04).

2.1. Configuración del Periodo y Cabecera Institucional

En el encabezado del documento, el usuario debe seleccionar el Mes, digitar el Año, y completar los datos institucionales (I.E., Nivel, Turno y Código Modular).

Automatización de Calendario: Al seleccionar el mes, el sistema estructurará el calendario exacto. Identificará y bloqueará estructuralmente los fines de semana en color rojo oscuro, impidiendo cualquier modificación accidental en dichos días no laborables.
2.2. Gestión del Personal (Indexación Automática)

Para registrar a un docente o auxiliar, el usuario únicamente debe ingresar el DNI en la Columna C, seguido de sus Nombres y Cargo.

  • Numeración Autogestionada: El sistema asignará automáticamente el número correlativo en la Columna B.
  • Reordenamiento: Si un registro es eliminado, el algoritmo reorganizará instantáneamente la numeración restante para mantener el orden.
2.3. Parámetros de Registro de Asistencia y Validaciones

El registro diario admite estrictamente las siguientes nomenclaturas oficiales: A (Asistencia), I (Inasistencia), T (Tardanza), 3T (Tercera Tardanza), P (Permiso), L (Licencia), H (Huelga).

Lógica de Validación para "3T": Por normativa, para registrar una Tercera Tardanza (3T), el docente debe contar con al menos dos registros previos de Tardanza (T) en el mes. Si el usuario intenta ingresar un "3T" sin cumplir esta condición, el sistema bloqueará la acción y emitirá una alerta preventiva.
2.4. Gestión Inteligente de Feriados Nacionales

El algoritmo cuenta con una base de datos interna de los feriados oficiales del Estado Peruano. Los días feriados se resaltarán automáticamente con un sombreado naranja suave y permanecerán vacíos por defecto para evitar confusiones con faltas o inasistencias.

Flexibilidad Operativa: Si la Institución Educativa dispusiera laborar en un día feriado, el usuario tiene total libertad para hacer clic en la celda vacía, desplegar la lista y registrar una asistencia regular ("A" u otra de la leyenda). El formato adaptará su diseño instantáneamente y retirará el color de feriado.
2.5. Transición al Siguiente Mes (Rutina de Inicialización)

Al concluir el mes, el usuario solo debe cambiar el nombre del mes en el menú desplegable superior (Ej. de Mayo a Junio).

El sistema ejecutará una Rutina de Limpieza Inteligente: eliminará todas las marcas de asistencia del mes anterior, pero mantendrá intacta la nómina del personal (DNI, Nombres, Cargos). El formato quedará listo para un nuevo periodo sin necesidad de volver a digitar al personal.

3. Operación del Anexo 04 (Reporte Consolidado)

Este documento es de carácter estrictamente automático. Consolida y totaliza los datos del Anexo 03 para la remisión de la planilla a la UGEL Ferreñafe.

3.1. Sincronización y Generación del Reporte

Procedimiento: El usuario no requiere ejecutar comandos, fórmulas ni botones. Basta con hacer clic en la pestaña inferior denominada "Anexo 04".

En fracciones de segundo, el sistema clonará toda la cabecera institucional, la nómina de personal y realizará el cómputo matemático exacto de inasistencias (I + 3T), tardanzas, permisos y huelgas.

3.2. Protección de Integridad y Zonas Editables

Para asegurar que los cálculos remitidos a la UGEL sean irrefutables, el Anexo 04 aplica automáticamente un protocolo de seguridad estructural:

  • Zonas Bloqueadas: Nombres, DNI, Totales de días de Inasistencia y Totales de veces de Tardanza se encuentran protegidos con un candado interno. Ningún usuario podrá alterarlos.
  • Zonas Editables (Ingreso Manual): Las columnas correspondientes a Horas y Minutos (de Tardanzas y Permisos), así como la columna de Observaciones, permanecen completamente libres. El directivo podrá digitar los tiempos cronológicos exactos con total normalidad.
Conservación de Datos: Si el usuario digita horas/minutos manualmente y posteriormente actualiza la asistencia en el Anexo 03, al retornar al Anexo 04, el sistema actualizará los totales, pero respetará y conservará intacta la digitación manual de las horas y minutos.

4. Protocolo de Resolución de Alertas

El archivo está diseñado para asistir al usuario mediante cuadros de diálogo si detecta inconsistencias operativas.

  • Alerta por modificación de Fin de Semana: Significa que el usuario intentó registrar un dato en Sábado o Domingo. El sistema deshará la acción instantáneamente para preservar el formato.
  • Alerta de Celda Protegida: Si el sistema de Excel indica que la celda está protegida, significa que se está intentando modificar una celda de cálculo automático en el Anexo 04. Es una medida de prevención.
  • Cero dependencias: Usted puede trabajar con absoluta tranquilidad sabiendo que el archivo carece de fórmulas. En caso de cometer un error tipográfico en horas o nombres, simplemente use la tecla borrar o deshacer con normalidad.
